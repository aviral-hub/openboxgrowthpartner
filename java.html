Evolution of Java

Key Founders

Java was created as a joint venture by key computer scientists:

  • James Gosling (Father of Java)
  • Patrick Naughton
  • Chris Warth
  • Ed Frank
  • Frank Sheridan

Historical Timeline

  • Fall 1992: Origin traced back to project development at Sun Microsystems. Originally named Oak.
  • 1995: Renamed from Oak to Java due to trademark conflicts, aligning with web application expansion.

Design Goals

Platform Neutrality

Java was originally conceived to serve as a platform-neutral language for embedded software running on various smart consumer electronic devices.

Problem

Traditional languages (like C/C++) relied on OS-specific compilers. Code built for one platform could not execute on another target machine without re-compilation.

Solution

Move to a fully portable, platform-independent runtime ecosystem capable of producing single, platform-neutral binary components.

Operating System & Hardware

Architecture Execution Flow

1
Source Code Creation: Write Java program files saved with the .java extension.
2
Compilation: The Java compiler translates source code into standard bytecode files saved with the .class extension.
3
Class Loading: The Class Loader reads both user-defined classes and core API library classes into memory.
4
Bytecode Verification: The Bytecode Verifier validates structure to ensure code does not violate security parameters.
5
Execution: The JVM converts bytecodes into machine code using interpretation and JIT compilation, interfacing directly with host OS/hardware.

The 5 Phases of Java Programs

1. Edit

Write and modify the Java code inside an editor or IDE. File saved as Welcome.java.

2. Compile

Translate source to bytecodes using javac Welcome.java. Generates Welcome.class.

3. Loading

Class Loader transfers bytecodes from storage into primary system memory for execution preparation.

4. Verify

Bytecode Verifier ensures formatting compliance and confirms security boundaries are enforced.

5. Execute

The JVM executes instructions via java Welcome, translating bytecode into machine-level instructions using interpretation and Just-In-Time (JIT) compilation.

Java Virtual Machine (JVM)

Execution Engine

  • Interpreter: Converts bytecode into machine instructions step-by-step.
  • JIT Compiler: Compiles frequently hit bytecode segments directly into native code for performance.
  • Adaptive Optimizer: Dynamically identifies "hot spots" in execution and compiles only those high-frequency paths.

Class Loader & Mobility

  • Class Loader: Handles security loading boundaries and enables loading over networks.
  • Platform Specificity: Bytecode is uniform globally, but the target JVM is tailored specifically to each target OS and hardware architecture.
