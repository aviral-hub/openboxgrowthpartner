1. Evolution of Java

The original design goal shaped the architecture we use today.

1992

Oak

The origin of Java can be traced to the fall of 1992. The language was initially called Oak.

1995

Java

Oak was renamed as Java in 1995.

Design Goal

  • Platform-neutral language
  • Portable and platform-independent
  • Move away from OS-specific compilers
  • Produce platform-neutral code

3. Compile-Time vs Runtime

Understanding these two environments makes Java Architecture easier.

Compile-Time Environment

  • Create Java source code using the .java extension.
  • Use the Java compiler.
  • Compiler creates bytecode.
  • Output is a .class file.

Runtime Environment

  • Class Loader reads classes into memory.
  • Bytecode Verifier validates bytecode.
  • JVM reads the bytecodes.
  • Execution interacts with the OS and hardware.

04

05
EXECUTE

5. What Is the JVM?

The runtime engine responsible for executing Java bytecode

JVM

  • The compiler produces bytecode.
  • Bytecodes are executed by the JVM.
  • JVM converts bytecode into machine-specific instructions.
  • The JVM is platform-specific.

Why does this help portability?

  • The same Java bytecode can execute in a wide variety of environments.
  • Only the JVM needs to be implemented for each platform.
  • Different JVMs interpret the same Java bytecode.

6. Class Loader & Bytecode Verifier

Important runtime components before execution

Class Loader

  • Loads compiled Java source files represented as bytecode.
  • Loads user-defined and library classes into the JVM.
  • Important from a security standpoint.
  • Important for network mobility.

Bytecode Verifier

  • Validates that bytecodes are valid.
  • Checks that security restrictions are not violated.
  • Comes after loading and before execution in the simplified flow.

7. Bytecode & Platform Independence

The .class file forms the bridge between source code and the JVM.
.java Java Source Code
→
.class Java Bytecode
→
JVM Platform-specific

Java Class File

Designed for platform independence and network mobility.

Important

The class file is compiled to a target JVM, but is independent of the underlying host platform.

Key Takeaway

Bytecode allows Java programs to run across different platforms through their JVMs.

8. Interpreter, JIT & Adaptive Optimization

Java execution can combine interpretation and on-the-fly compilation.

Interpreter

  • JVM can begin by interpreting bytecodes.
  • Bytecode is translated into machine-specific instructions.

JIT / Native Code

  • Java can compile bytecode into native code on the fly.
  • This can make frequently executed code faster.

Adaptive Optimizer

  • Tracks code that is running.
  • Identifies heavily used areas.
  • Compiles heavily used areas into native code.
  • Less-used code can continue to be interpreted.
